# 이름·타입·구조를 먼저 개선하는 Rust 클린코드

## 판단 순서와 권위

주석을 감추고도 주요 내부 값의 역할·단위·상태와 함수 책임을 읽을 수 있는지 살핀다. 이해가 막히면 먼저 이름·타입·책임·흐름의 원인을 고친다. 원본 주석을 번역하거나 삭제하는 것만으로 끝내지 않는다. 명확한 표현은 유지한다.

문법·플랫폼 제약과 보존해야 하는 외부 계약을 우선한다. 그 안에서 대상 저장소 규약과 Rust 관례를 적용한다. 내부 식별자 개선을 JSON 키·프로토콜·공개 호출명 변경으로 확대하지 않는다. 계약 때문에 유지하는 이름은 내부 이름과 경계에서 대응시킬 수 있다.

## 의미 있는 이름

- 함수·메서드·모듈·필드·지역 값은 `snake_case`, 타입·trait·enum variant는 `UpperCamelCase`, 상수·static은 `SCREAMING_SNAKE_CASE`를 기본으로 한다. 약어는 `HttpClient`, `Uuid`처럼 쓴다. 외부 바인딩·trait·생성 코드의 이름 제약을 존중한다.
- `data`, `process`, `manager` 같은 이름이 실제 역할을 숨기는지 확인한다. 도메인 책임과 변환 의미를 드러내되 관용적인 짧은 지역 이름까지 무조건 늘리지 않는다.
- 수치는 단위가 드러나게 한다. `timeout_ms` 또는 의미가 맞는 `Duration`처럼 표현하고 외부 표현의 단위를 보존한다. 불리언은 참일 때의 의미가 읽히게 한다.
- `as_`·`to_`·`into_`는 빌림·변환·소유권 의미와 맞춘다. `pub`와 이름 케이스·접두사를 혼동하지 않는다. C++ 멤버 표식을 Rust 전체에 이식하지 않는다.

예: 만료 항목을 세는 `n`을 역할이 필요한 범위에서 `expired_item_count`로 바꾸면 ‘만료 항목 수’라는 복창 주석이 필요 없어진다. 이름만 바꿔 숨은 삭제 부작용까지 정당화하지는 못한다.

## 타입과 책임

- 유효 상태를 구분할 때 enum, 혼동할 수 있는 값에 newtype, 부재에 `Option`, 복구 가능한 실패에 `Result`를 사용한다. 타입 별칭은 별개 의미의 값 혼용을 막지 않는다. 필요한 의미 구분이 없으면 새 추상화를 추가하지 않는다.
- 외부 예외·종료 코드·실패 전 부작용은 경계에서 기존 의미로 대응시킨다. panic→Err, 누락→기본값도 관찰 동작을 바꿀 수 있다. Rust 관용성을 명분으로 임의 변경하지 않는다.
- borrow·소유권·자원 수명으로 관계를 드러낸다. 컴파일러를 만족시키기 위해 불필요한 clone·공유 가변 상태·unsafe로 우회하지 않는다. 근거가 있는 복사는 스타일 위반으로 취급하지 않는다.
- 혼재한 책임이나 제어 흐름이 부작용을 숨길 때 분리한다. 실행 순서·부분 실패·원자성·락 범위·비동기 취소 동작을 보존한다.
- 함수 길이·추출 개수·주석 비율은 합격 기준이 아니다. 지나친 계층·범용 추상화·무조건적인 짧은 함수도 이해를 해칠 수 있다.

## 주석과 rustdoc

공개 API에는 호출자 관점의 간결한 사용 계약을 기본으로 남긴다. 이름·타입을 문장으로 반복하는 항목별 틀을 양산하지 않는다. 해당하는 오류·부작용·전제조건·소유권·panic 조건을 설명하고 예제는 이해·오용 방지에 필요할 때 쓴다. 문서화를 위해 공개 범위를 늘리지 않는다.

코드만으로 표현되지 않는 다음 정보는 필요한 위치에 보존한다.

- 비자명한 구조·알고리즘·우회 방식을 유지하는 확인된 근거.
- 호환성 때문에 유지하는 이상 동작과 바꾸면 깨지는 계약.
- 실패 전 부분 상태 변경 등 시그니처만으로 알 수 없는 계약.
- `unsafe` block/impl의 `SAFETY` 근거와 실제 수명·정렬·별칭·동시성 불변조건. `unsafe fn`에는 호출자 의무를 `# Safety`로 설명한다. ‘안전하다’라는 선언만으로 대체하지 않는다.

줄별 동작 번역, 이름 복창, ‘무결성을 보장한다’ 같은 검증되지 않은 설명은 제거·교정한다. WHY만 허용한다며 API 계약·안전 근거를 삭제하지 않는다. 라이선스 고지·코드 생성 표식·도구 지시 주석은 구분해 보존한다.

원본 주석을 현재 코드와 대조한다. 낡은 설명은 고치고 확인하지 못한 역사적 의도·미측정 최적화 효과는 발명하지 않는다. 긴 설계 일지·규칙 준수 표는 코드 안에 넣지 않는다. 필요한 이유만 짧게 연결한다.

주석 언어는 과업 지정과 대상 저장소 관례를 따른다. 둘 다 없고 선택이 필요하면 확인한다. 스킬 지침의 언어를 변환 대상 전체에 강제하지 않는다.

## 종료 판단

변경 이유를 구체적인 의미 혼동·책임 혼재·잘못된 설명·필수 정보 누락과 연결할 수 있어야 한다. 그 문제가 해소되고 필요한 계약·근거가 정확히 남으면 정리를 끝낸다. fmt/build/Clippy는 이 의미 판단을 대신하지 않는다.
