# Rust 전환 하네스: 공개 프로젝트 조사와 seed 적재요청

조사일: 2026-11-03 KST. **먼저 P0의 5개 저장소를 참고 원본으로 적재하고, 언어 도구는 기본 Claude Code의 공식 Rust LSP부터 검토하는 방안을 권장한다.** Codex 워커에 필요한 언어 질의가 부족하면 M1, Python/Rust 양쪽 탐색이 필요하면 M2를 비교한다. 이 우선순위는 이번 맥락에 대한 조사자의 제안이며 채택·설치 승인 기록이 아니다.

이번 결과는 다운로드·clone 가능한 취득 안내다. 외부 후보를 seed에 clone하거나 설치·활성화·빌드·실행하지 않았다. 조사용 공개 텍스트만 temp에 수집했다. 후보 스킬의 자연어 지침, MCP의 호출 인터페이스, 최종 합격을 판정할 검증 실행기를 구분한다.

## 1. 원본 보고서에서 이어받을 조건

- [Python→Rust 하네스·검증 루프 분석](<../../seed/h_report 모음/h_report_26110101_Python_Rust_전환_하네스와_검증_루프_분석.md>): 전체 재작성보다 병목 경계의 부분 이식, 원본 동작·성능·wheel 검증, 보호된 검사기와 유한 수정 루프를 제안한다.
- [스킬·연결 도구 후보 원장](<../../seed/h_report 모음/h_report_26110101_Rust_전환_스킬과_연결_도구_조사_자료.md>): 기존 6개 스킬과 4개 연결 후보의 정확한 경로·고정 revision·제약을 제공한다. 보고서의 검수는 설치·런타임 성공 근거가 아니다.

원본은 Hermes·경리나라 환경을 다뤘다. 현재는 **val_agent의 Codex가 지휘하고, target_project의 Claude Code를 기본 워커로, 요청 시 Codex CLI를 선택**한다. 기존 [worker-agent-control](../../.agents/skills/worker-agent-control/SKILL.md)을 지휘 계층으로 유지한다. Hermes 내장 LSP와 과거 절대 경로는 이 프로젝트 설치 요구에서 제외한다. worker에게 실제로 필요한 언어 도구·지침은 worker 프로젝트에 적용해야 하며 val_agent의 seed 보관만으로 전파되지 않는다.

### 4.1 최초 P0 5개 clone

아래 명령은 **사용자가 실행할 안내이며 이번 조사에서는 실행하지 않았다.** 대상 디렉터리가 없는 최초 취득용이다. `--no-checkout`으로 받은 뒤 조회한 SHA를 detached checkout한다. 기존 경로가 있다면 덮거나 삭제하지 말고 `git -C 경로 status --short`와 `git -C 경로 rev-parse HEAD`로 먼저 확인한다. 스크립트 안에서 오류가 나면 중단하도록 한다.

```bash
set -e

mkdir -p seed/rust-harness
```

## 6. 적재 후 어디에 적용할 것인가

### Codex 지휘와 worker 환경을 구분한다

- `val_agent/seed/rust-harness/`: 참고 원본 보관. 프로젝트 규칙상 Git 제외 경로다. 이곳에 받은 자료는 자동 설치되지 않는다.
- `val_agent/.agents/skills/`: 향후 Codex 지휘용으로 선택·조정한 스킬의 설치 위치. worker의 Rust 구현 지침까지 이곳에만 두면 worker가 발견한다고 보장할 수 없다.
- `target_project`의 worker 설정: 실제 Rust 구현에 쓸 스킬·LSP/MCP는 worker가 사용하는 호스트와 workspace에 적용한다. Claude Code와 Codex CLI는 각자의 발견 경로·config·세션 도구를 확인한다.

OpenAI 공식 [Build skills](https://learn.chatgpt.com/docs/build-skills)는 Codex의 repository `.agents/skills` 발견을 설명한다. [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)는 신뢰 프로젝트의 `.codex/config.toml`을 지원한다. 이 문서는 해당 경로를 조사했으며 실제 설정을 추가하지 않았다. 원저장소의 Claude 설정 JSON을 Codex TOML로 복사만 하거나 Claude hooks/lspServers를 동일하게 처리한다고 가정하지 않는다.

기본 Claude Code 워커에는 공식 P1을 먼저 비교한다. Anthropic의 [설치 관리 문서](https://code.claude.com/docs/en/discover-plugins)에 따르면 `claude -p` 안에서 `/plugin`은 동작하지 않으며, 이미 설치한 플러그인이 로드된다. 따라서 향후 활성화는 worker 저장소에서 네이티브 shell 관리 명령과 scope로 수행하고, 실제 비대화형 작업에서 연결을 다시 확인해야 한다. val_agent에서 실행한 관리 명령이 worker 프로젝트에 적용됐다고 간주하지 않는다.

### 최소 조합 제안

1. **부분 PyO3 이식:** S1의 동작 목록·테스트 대응 + S2의 PyO3 참고 + S3/S4의 필요한 리뷰·검사 지침, B1/B2와 기존 Python 검사 환경을 사용한다.
2. **기본 Claude worker 언어 지원:** P1 + 준비된 rust-analyzer를 우선 비교한다. 부족한 기능이 확인될 때만 M1/M2 하나를 선택한다.
3. **Codex worker:** 선택한 Codex 스킬과 필요 시 M1을 검토한다. 혼합 Python/Rust 탐색의 이점이 크면 M2를 비교하되 두 MCP를 기본 중복 설치하지 않는다.
4. **전체 패키지 재작성:** S6의 작업분해만 먼저 검토한다. 현재 지휘 구조를 바꾸거나 외부 공개 저장소 생성·자동 설치를 허용한 것으로 해석하지 않는다.

## 7. 이 후보들이 대신 제공하지 않는 검증 하네스

이번 확인 범위에서 **기존 Python 계약·보호된 oracle·single/multi/shared 성능·실제 wheel·유한 수정 상한을 현재 worker에 연결해 강제하는 완성된 일괄 패키지는 확인하지 못했다.** 따라서 seed 자료를 확보한 다음 기존 실행기·CI에서 다음 부족분만 설계한다. 공개 프로젝트 전체에 그런 패키지가 없다는 주장은 아니다.

| 고정할 항목 | 후속 파일럿에서 필요한 실제 근거 |
|---|---|
| 대상과 동작 | 프로파일링된 작은 경계, API·타입·순서·예외·정수/부동소수·부수 효과 계약 |
| 원본 보호 | 기준 Python·기준 테스트·합격 설정의 승인 revision과 worker 쓰기 범위; 사후 diff와 예방 권한의 구분 |
| Rust 검사 | fmt/check/clippy/test의 실제 종료 코드·테스트 분모·toolchain·features·target; 필요 시 별도 doctest |
| 동작 비교 | 양쪽에 독립 입력 복사, 회귀·경계·속성/차등 검사; 원본 결함은 명세와 검토로 판정 |

MCP가 Cargo를 실행해도 worker가 호출을 생략하면 필수 검사가 되지 않는다. 컴파일·Clippy 통과는 Python 의미 동등성·성능 향상의 증명이 아니다. 조건이 바뀌면 영향받은 검사만 재수행하고 유효한 기존 근거는 재사용한다.

## 8. 조사·검증의 정확한 범위

- 두 로컬 보고서의 후보·제약·현재 버전 보완과 설계 제안을 읽었다. 원본 문서는 수정하지 않았다.
- 17개 원저장소의 API 메타·기본 branch HEAD 및 선택 원문을 읽었다. 원문 URL은 위 고정 SHA로 복구할 수 있다. 하네스 12개, 기반 5개 모두 조회 당시 archived=false였으나 이는 유지보수 품질 인증이 아니다.
- 라이선스 누락 2곳(S5/M4)은 recursive tree의 truncated=false를 확인했다. S7의 상충 표기는 해소됐다고 기록하지 않았다.
- 비교 검색에는 `Rust Python migration agent skill SKILL.md PyO3 maturin github`, `Rust MCP server cargo check clippy test github rust-mcp` 등을 사용했다. 원저장소를 근거로 삼았으며 디렉터리 사이트의 요약·별점은 검증 근거로 쓰지 않았다.
- 추가 검색의 dexwritescode/rust-mcp와 py2many/static-python-skill은 저장소 소개까지만 열람했다. 전자는 M1과 기능이 겹치고 후자는 static Python 전처리 범위라 이번 우선 적재 원장 12개에는 넣지 않았다. 이 제외는 기술적 결함 판정이 아니다.
- 원문·API·검색은 조사 증거이고 ZIP 다운로드·Git checkout·빌드·실제 MCP tools/list·worker 호출·성능 시험의 성공 증거가 아니다. 이번 과업은 조사 문서 발행으로 종료한다.

## 9. 요청할 첫 적재 묶음

**이번에 직접 받아 둘 목록은 S1·S2·S3·S4·P1의 5개다.** 부분 Python 확장 이식 자료를 함께 보관하려면 B1·B2를 더한다. Codex 언어 질의 실험을 계획하면 M1을 추가하고, 혼합 언어 탐색 실험이면 M1과 M2 중 선택한다. 나머지는 제약을 검토할 때 선택적으로 받는다.

다운로드 후에는 선택한 저장소명·SHA·seed 경로만 인계하면 후속 설치 과업을 구체화할 수 있다. 코드 변환 대상·지원 Python/ABI·성능 임계값은 아직 합의하지 않았으므로 이번 자료의 존재를 변환 착수나 전체 재작성 승인으로 취급하지 않는다.
