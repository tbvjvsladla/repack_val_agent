# 헌장과 wiki-desk 설치의 요구 합의

## 목표와 합의
사용자와 우로보로스 딥 인터뷰를 거쳐 두 헌장(작업수행규칙·문서발행규칙)을 먼저 정립하고 Codex 전용 프로젝트 로컬 wiki-desk를 설치한다.
- 루트 AGENTS.md가 .codex/rules/workflow.md와 .codex/rules/docs.md를 읽도록 연결한다.
- 새 과업은 interview·plan·devlog·checklist 네 역할별 문서로 기록한다. 같은 과업의 후속 수정은 기존 경로에서 갱신한다.
- 문서는 공통 task_id 및 관련 문서 링크로 연결한다.
- 파일명은 YYMMDDHH_한글제목.md, 같은 역할·시간 충돌 시 YYMMDDHH_MM_SS_한글제목.md이다. 시각은 Asia/Seoul이다.
- Planner가 구현 전 plan·checklist 기준을 작성하고, 메인이 Planner→Builder→Validator 순서로 수행한다.
- 독립 검증은 사용자 요청·고영향 변경·반복 실패/가정 점검·plan의 사전 지정 시 수행한다. 이번 초기 설치는 최종 독립 Validator를 둔다.
- 일반 완료는 모든 적용 항목 통과다. 실패·미실행은 보존하고 사유·잔여 위험·후속 조치와 사용자의 명시 승인으로 예외 승인 종료를 구분한다.
- 위키의 source_roots는 docs/ 하나다. 원본 seed/wiki-desk는 보존한다.
- Git을 초기화하고 헌장·설치 스킬·문서·위키 데이터를 추적한다. 루트 seed/·temp/·tests/·검색 캐시·우로보로스 실행 데이터는 제외한다.
- 검증 임시 코드는 temp/ 또는 tests/에 둔다.

## 보완안의 사용자 채택
사용자가 R1–R5를 승인했다: 검사·리뷰·수용 구분, 비례 검증·증거 재사용과 중단 조건, 독립 Validator 권한, 기존 변경 보존·재개, 설치별 증거와 최소 Seed 메타데이터.
새 검증 프레임워크나 범용 해시·백업·저널·형식 증명 도구를 도입하는 요구는 아니다. 이미 승인된 네 문서 원칙과 단일 메인 루프를 유지한다.
