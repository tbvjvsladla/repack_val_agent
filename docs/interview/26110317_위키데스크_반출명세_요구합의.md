# 위키데스크 반출명세 요구합의

## 요청과 범위

wiki-desk 원개발·관리 주체에게 전달할 SDD 패치 명세를 `seed/spec.md`로 작성한다. 클린룸과 SDD를 웹 조사하고 현재 설치·헌장에 네 항목이 반영되었는지 확인한다. 구현·원본 패키지 수정·외부 전송은 요청 범위 밖이다.

## 사용자 최신 결정

사용자는 후속 메시지에서 다음 경계를 명확히 정했다.

- 1번 네 문서 역할 폴더, 2번 작업수행·문서발행규칙, 3번 검증 최적화·하네스는 **모든 수용자에게 권장**이다. 스킬만 설치하거나 기존 docs·규칙을 유지할 수 있어야 한다.
- 헌장 신설·개정은 배포받은 수용자가 수용 여부를 검토해야 한다. 설치 요청만으로 개정 권한을 추론하지 않는다.
- 4번 Claude 외 Codex 지원 확장은 필수 패치 요구다.
- 현재 프로젝트에서 1·2·3이 이미 채택된 사실은 다른 프로젝트의 채택 의무나 승인 근거가 아니다.

## 인터뷰와 반출 경계

우로보로스 인터뷰 `interview-public-004`에서 반출 경계를 질문했고 보조 검토를 수행했다. 사용자의 응답은 원문 포함 선택 대신 위의 권장/필수 구분을 정정한 것이다. 이를 원문 반출 승인으로 해석하지 않는다.

보수적으로 구현 코드·현재 헌장 원문·로컬 로그를 반출 명세에서 제외하고, 동작·권장사항·제약·수용기준을 새로 작성한다. 내부 검증 근거는 이 과업 문서에 둔다. 엄격한 클린룸의 수신자 미노출이나 법적 효과를 입증했다고 주장하지 않는다. 명세 작성이 목적이므로 실행용 Ouroboros Seed 생성·실행·인터뷰 완료 판정은 하지 않는다. 추가 인터뷰가 필요한 구현상 결정은 수신자의 설계 영역으로 표시한다.

## 완료 기준

`seed/spec.md`가 독립적으로 읽히며 권장 3항목과 필수 Codex 지원을 구분하고, 설치만/기존 구조/선택 채택/거절 시나리오 및 추적 가능한 요구·수용 기준을 갖춘다. 웹 출처, 현행 적용 확인과 한계를 구분한다. 내부 네 문서를 연결하고 위키에 입고한다.
