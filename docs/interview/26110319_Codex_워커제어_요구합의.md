# 목표와 확정 범위

사용자는 `seed/hermes-subagent-control-plane`의 두 브랜치에 있는 Hermes용 스킬을 이 프로젝트의 Codex 전용 로컬 스킬로 이식·설치하도록 요청했다. 워커 대상은 `/workspace/target_project`다.

- 지휘자: val_agent의 Codex만 사용. 사용자 답변: “이 val_agent는 codex로만 사용할거야”.
- 워커: 기본 Claude Code, 명시 요청 시 Codex CLI. 사용자 선택: “2. 기본 Claude Code, 요청하면 Codex CLI 이거로”.
- 원본의 실제 브랜치: `origin/claude-code-control`, `origin/codex-cli-control`. 새 Git 브랜치를 만들라는 요청이 아니다.
- 설치 위치: 이 저장소 `.agents/skills/`. 원본 seed, 워커 프로젝트, 사용자 전역 설정은 수정 대상이 아니다.
- 선택한 CLI의 실패를 다른 실행자의 성공으로 대체하지 않는다. 기존 과업·승인·산출물을 보존한다.

# 확인한 사실

- 공식 문서 [Build skills](https://learn.chatgpt.com/docs/build-skills)를 실제 열어 확인했다. 저장소 스킬 경로는 `.agents/skills`, 필수 파일은 name·description frontmatter가 있는 `SKILL.md`다.
- 원본 스킬은 v4.3.0이며 Hermes의 `skill_view`, `terminal`, `process`, `HERMES_SKILL_DIR`를 사용한다. Codex 실행 도구와 설치 경로에 맞춰 조정해야 한다.
- 워커의 현재 체크아웃은 single-node이며 multi-node·hint 브랜치도 있다. 스킬 원본의 두 브랜치와 별개다. 워커 브랜치는 이번 설치에서 전환하지 않는다.
- 워커 `AGENTS.md`는 공통 헌장 `CLAUDE.md` 및 실제 체크아웃의 workflow·docs·strategy.topology 지침을 따르게 한다. agent-card.json은 현재 조회에서 확인되지 않았다. 카드의 존재나 내용을 만들어내지 않는다.
- Codex·Claude 설치 CLI의 도움말을 읽었다. 원본에 적힌 옵션은 현행 CLI 계약과 대조해야 한다.
- 기존 위키 조회에서 hermes/control-plane 관련 선행 과업은 발견되지 않았다(원문 문서 8개 범위).

# 인터뷰 결과

Ouroboros 인터뷰 `interview-public-005`을 이어서 사용했다. 사용자는 “1. 실제 호출까지 검증”을 선택했다. 두 CLI 각각 대상의 실제 지침·정체성을 보고하고, 호스트가 경로·provider·브랜치·읽은 지침과 Git 전후 상태를 대조하는 기준이다. 빌드·서빙·파일 편집은 이번 설치 검증의 대상이 아니다.

Ouroboros는 ambiguity 0.01에서 인터뷰 완료를 반환했다. 별도 closer는 seed_ready, contrarian은 medium(읽기 도구 제한과 Git 관측 범위 구분), gap_hunter는 low(문서 최신화·실행 근거 기록)로 판단했고 사용자 판단이 필요한 blocker는 없었다. Git 비교는 ignored 파일과 CLI의 사용자 영역 기록까지 검증하지 않는다.

별도 Seed 생성은 하지 않는다. 사용자가 이미 요청한 설치·실제 검증을 이 네 문서의 기준에 따라 수행한다. 인터뷰 종료를 설치 완료로 취급하지 않는다.

## 구현 중 권한 확인

Codex read-only sandbox의 bwrap 초기화가 실패했다. 실패 기록을 유지하고 워커에 이미 설정된 `:danger-full-access` 프로필을 상속해 파일 수정 없는 과제를 새 호출로 검증하는 실행 승인을 요청한 뒤 실행했다. 기존 워커 설정은 바꾸지 않았다. 성공 호출은 OS read-only sandbox가 아니라 상속된 기존 권한에서의 읽기 전용 과제이며, 이 차이는 완료 보고에서도 유지한다.
