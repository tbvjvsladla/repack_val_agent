# plan/ 문서 작성 가이드

이 폴더의 `doc_gen_guide.md`는 Git으로 배포하는 작성 안내다. 실제 과업 문서는 같은 폴더에 작성하며 Git 추적·공개본에서 제외한다. 기존 로컬 문서도 지우지 않는다.

공통 규칙의 정본은 [문서발행규칙](../../.codex/rules/docs.md), 수행·승인·검증의 정본은 [작업수행규칙](../../.codex/rules/workflow.md)이다. 이 가이드는 실제 과업 기록이나 승인 근거가 아니다.

## 역할과 작성 시점

interview의 목표를 수행 순서와 검증 가능한 완료 기준으로 바꾼다. 구현 전에 작성하고 checklist 초안과 함께 Builder가 사용할 입력을 제공한다.

## 반드시 담을 내용

- 현재 구조·문제, 목표·범위·허용 경로와 보존 계약.
- 단계별 작업, 영향 받는 인터페이스·환경·의존성·지원 조합.
- 선택한 도구·역할, 각 입력·산출물, 연결 순서·권한과 실패 시 반환 조건.
- 기대 조건과 실제 관측을 연결할 검증 계획. 필요한 독립 검증과 최종 수용의 경계.
- 실패·중단 시 보존할 자료, 복구·재개 지점과 남은 결정.

성능 개선 과업이면 실행 전에 원본 기준선·대표 workload·동일 환경·품질 조건·판정 기준을 정한다. Rust 전환 자체를 개선 성과로 쓰지 않는다. 구현 중 범위를 바꿀 때는 이유와 영향, 필요한 사용자 결정을 기록한다.

## 작성과 갱신

- 파일명은 `<YYMMDDHH>_<한글제목>.md`이며 실제 Asia/Seoul 발행 시각을 사용한다. 같은 역할 폴더의 같은 시간대에 이미 발행한 문서가 있으면 `<YYMMDDHH_MM_SS>_<한글제목>.md`로 충돌을 피한다. 역할 접두사를 붙이지 않는다.
- 기존 과업의 후속 기록은 같은 `task_id`와 기존 파일 경로에서 갱신한다. `updated`와 본문 변경 이력에 변경 시점·이유를 남기며 과거 승인·실패 기록을 보존한다.
- frontmatter의 `related_*`는 저장소 상대 전체 경로, 본문의 클릭 링크는 이 문서 위치에서 해석되는 상대 경로로 적는다.
- 발행·갱신 뒤 로컬 위키에 입고한다. 실제 명령·보호 절차는 문서발행규칙을 따른다. 이 가이드 자체는 입고 대상에서 제외한다.

## 시작 예시

아래 값은 합성 예시다. 실제 시각·제목·상태·과업 ID와 존재하는 문서 경로로 바꾼다.

```yaml
---
task_id: sample-refactor-261106090000
document_type: plan
title: 예시 리팩토링 plan
status: draft
created: 2026-11-06T09:00:00+09:00
updated: 2026-11-06T09:00:00+09:00
related_interview: docs/interview/26110609_예시_리팩토링.md
related_devlog: docs/devlog/26110609_예시_리팩토링.md
related_checklist: docs/checklist/26110609_예시_리팩토링.md
---
```
