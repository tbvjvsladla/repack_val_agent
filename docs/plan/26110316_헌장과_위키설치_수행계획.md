# 헌장과 wiki-desk 설치 수행 계획

## 완료 기준
관련 checklist의 C1–C7을 구현 전에 정했다. 이 계획의 수용 기준은 사용자 승인 Seed v1.1.0이며 구현 결과에 맞춰 완화하지 않는다.

## 수행 순서
1. 인터뷰 합의를 기록하고 plan·checklist를 작성한다.
2. AGENTS.md 진입점과 작업수행규칙·문서발행규칙을 정립한다.
3. wiki-desk 전체 패키지를 .agents/skills/wiki-desk/에 복사하되 .git을 제외하고 Codex 지침을 적용한다.
4. docs 전용 계약, 무접두 파일명과 역할별 분류를 맞추고 init·sync 계획을 확인한 뒤 적용한다.
5. Git 초기화와 루트에 한정한 제외 규칙을 적용한다.
6. 기존 manifest·회귀 테스트·문서/명명/링크·docs 전용 sync/check·query/read·실제 Codex 발견/로드를 확인한다.
7. 별도 Validator에게 현재 대상과 근거를 넘겨 확인하고 기존 checklist에 결과를 기록한다.

## 검증과 증거
원본 패키지는 git 상태와 기존 manifest로 확인한다. 설치본은 manifest와 회귀 검사를 실행한다. 문서·명명·링크 및 운영 스모크는 temp/bootstrap-validation/의 표적 검사와 로그로 확인한다.
독립 Validator는 출처·대상·환경이 일치하는 결과를 재사용하고 필요한 추가 검사만 수행한다. 제품 소스·헌장을 직접 수정하지 않는다.
CLI check 하나를 실제 Codex 로드나 전체 설치 성공의 증거로 삼지 않는다.

## 영향과 복구
현재 대상 경로의 기존 파일을 확인하고 사용자 변경을 보존한다. 초기 설치의 신규 산출물과 수정 범위를 기록한다.
중단 시 devlog에 완료·미완료와 재개 명령을 남기며 확인된 유효 결과는 재사용한다. 충돌·소유 불명 파일을 삭제하거나 전체 재설치로 덮지 않는다.
