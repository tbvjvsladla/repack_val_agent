# 완료 기준

- 프로젝트 로컬 설치본이 Codex용으로 발견 가능한 구조다.
- 기본 Claude Code와 명시 Codex CLI 선택이 분명하고 암묵적 대체가 없다.
- 실제 워커 경로와 네이티브 지침·권한을 사용하며 Hermes 전용 도구에 의존하지 않는다.
- 수정한 실행 스크립트가 있다면 관련 성공·실패 동작을 실행 검증한다.
- 두 CLI 각각 실제 읽기 전용 discovery가 성공하고 workspace/provider/branch/context를 직접 대조한다. Git 전후 관측은 기존 dirty 상태를 보존하며 status·HEAD·tracked diff를 비교한다. ignored 파일·CLI 사용자 영역 무변경까지 주장하지 않는다.
- 별도 Validator가 요구·설치본·실행 근거를 읽고 CLI 선택·권한·성공 판정의 결함을 독립 검토한다.

# 확정 구현 선택

공통 제어 절차는 하나의 `.agents/skills/worker-agent-control`에 설치한다. 두 CLI별 차이는 references/execution.md와 읽기 전용 과제용 scripts/discover.py에 둔다. config.json이 사용자 지정 대상과 기본 Claude 선택을 소유한다. 본작업은 스킬 지침에 따라 네이티브 CLI로 위임하며 discovery 스크립트를 범용 실행 우회점으로 만들지 않는다.

## 실행 중 확인한 환경과 조정

Codex 첫 read-only sandbox 호출은 이 호스트의 bwrap 초기화 오류로 파일을 읽지 못했고 FAIL로 보존했다. 사용자 완료 기준은 파일 수정 없는 실제 호출이지 OS sandbox 자체의 통과가 아니다. 실패 후 실행 승인 요청을 거쳐 `--codex-permissions inherit` 명시 옵션으로 새 attempt를 수행했다. 이 옵션은 기본 동작을 바꾸지 않고 워커에 이미 설치된 `:danger-full-access`를 상속한다. 실제 파일 읽기·정체성 및 Git 전후 비교는 통과했다. 이를 OS read-only 강제 성공으로 보고하지 않는다. 상세 근거·독립 검토는 checklist에 있다.

# 보존·재개

다수의 기존 staged/untracked 변경은 다른 과업의 작업물이다. 덮어쓰거나 stage·commit·reset하지 않는다. 신규 설치 경로에 기존 파일이 있으면 먼저 차이를 확인한다. 중단 시 이 네 문서와 실행 로그에서 남은 항목부터 이어간다.
