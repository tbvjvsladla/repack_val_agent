# 공개배포 수행계획

## 입력과 도구

메인 에이전트가 Planner → Builder → 자체검사 역할을 순차 수행한다. 외부 공개의 영향 때문에 별도 `public_validator`가 코드·공개 후보·문서 보존과 제외 경계를 직접 검사한다. 이 검증자는 검토 대상과 수용 기준을 수정하지 않고 원시 관측과 지적을 반환하며, 메인은 수정 후 재검증을 요청한다. wiki-desk는 기존 결정의 원문 조회와 이번 네 문서의 입고에만 사용한다. Git 조회는 추적·이력·제외 경계 확인에, Python 표준 라이브러리로 작성하는 공개본 생성기는 허용 경로 복사·문서 익명화에 사용한다. Node.js는 공개본의 위키 재생성과 설치 스킬 자체검사에 사용한다. Rust 변환·외부 워커·Harness² 실험 자체는 실행하지 않는다.

## 구현 순서와 허용 변경

1. 현재 Git 추적 상태와 공개 후보를 읽고 민감정보 유형을 분류한다. `.gitignore`가 이미 추적한 파일이나 과거 커밋을 제거하지 않는다는 경계를 명시한다.
2. 루트 `.gitignore`, README, MIT LICENSE, 출처·공개 안내, 공개본 생성기와 워커 설정 예시를 추가한다. 기존 스킬 코드·원본 작업 이력·개인 설정을 수정하지 않는다.
3. 공개본 생성기는 허용 경로만 새 디렉터리에 복사한다. 원본 `.git`·실제 config·`seed/`·실행 데이터는 복사하지 않는다. 문서의 환경값은 익명화하고 위키는 익명화 문서에서 다시 만든다. 알려진 자격증명 형태가 있으면 발행 후보 생성을 실패 처리한다.
4. 원본 문서 입고는 sync 계획을 확인한 뒤 적용하고 check한다. 보호 카드·타 세션 변경이 나오면 덮어쓰지 않고 원인을 기록한다.
5. 공개 후보에 대한 포함·제외·익명화, 위키 정합성, 스킬의 적용 가능한 자체검사를 수행한다. 원본 이력과 사용자 설정 보존을 확인한다.
6. 공개 후보 검토가 끝나면 별도 저장소에서만 커밋과 GitHub 발행을 시도한다. 원격·인증 부재는 실제 결과대로 남기고 토큰 조회나 전역 인증 변경을 하지 않는다.

## 완료 기준과 재개

공개 범위·제외 범위·MIT·원본 로그 부재에 따른 검증 한계가 문서로 설명되고, 공개본에 승인 범위의 파일만 들어가야 한다. 공개본 검증과 원격 발행은 별개로 기록한다. 원격 인증이 없으면 공개본 준비까지만 완료하며 발행은 NOT_RUN/BLOCKED로 남긴다. 다음에는 기존 공개본과 checklist의 미완료 항목부터 재개한다. 다른 세션의 현재 과업 수용 여부를 변경하지 않는다.

## 실제 종료

공개 후보 v2의 별도 검증 PASS 후 SSH로 새 `main`을 발행했다. 원본 Git 이력과 대상 프로젝트는 보존했다. 공개 자체의 완료는 해당 공개 구성과 발행에만 적용되며 Rust 리팩토링 전체의 완료를 뜻하지 않는다. 수행·검증 결과는 같은 과업의 devlog/checklist에 기록하고 공개 저장소에도 후속 반영한다.
