# Rust 하네스 조사 수행계획

## 완료 기준과 수행 계획

1. 두 원본 보고서의 후보·한계·검증 계약을 읽는다.
2. 공개 원저장소와 공식 문서로 후보의 경로·기능·라이선스·조회 revision을 확인한다. 기존 후보 외 유의미한 스킬·MCP 대안도 검색한다.
3. request 문서에 최소 우선 적재 묶음, 조건부·보류 후보, 정확한 clone/ZIP 경로, 필요한 하위 디렉터리, 적용 호스트와 후속 검증을 작성한다.
4. 문서 간 링크·후보 분모·취득 명령과 원문 근거를 자체 검사하고 wiki-desk sync 계획을 확인한 후 입고·check한다.

원본·기존 스킬·워커·헌장·위키 계약은 수정하지 않는다. Git의 기존 staged/unstaged 변경을 유지한다. 취득 명령은 안내로만 발행하고 실행하지 않는다. 독립 검증을 필수화할 고위험 실행 변경은 없다. Builder 작성 후 같은 메인 에이전트가 Validator 역할로 문서와 근거를 대조한다.
