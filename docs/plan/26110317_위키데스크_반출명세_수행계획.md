# 위키데스크 반출명세 수행계획

## 수행 순서

1. 두 헌장·스킬을 읽고 wiki-desk query/read로 이전 설치 근거를 확인한다. 원본 안내에도 헌장 연계가 있다는 사실을 보존한다.
2. 클린룸·SDD·Codex 공식 자료를 확인하고 최신 사용자 결정에 따라 배포물의 안내 책임과 수용자의 선택권을 분리한다.
3. 이 계획과 checklist 초안 뒤 `seed/spec.md`에 요구 ID·선택 권고·필수 제약·수용 시나리오·수신자 수행 순서·완료 기준을 작성한다.
4. 문서 내용과 링크·메타·권장 거절 시나리오를 점검한다. 현재 패키지 manifest를 확인해 과거 회귀 근거의 재사용 범위를 판단한다. 런타임 변경이 없으면 전체 회귀는 반복하지 않는다.
5. 같은 과업의 네 문서를 결과로 갱신하고 sync 계획을 확인한 뒤 적용·check한다. seed는 입고하지 않는다.

## 범위와 검증

새로운 문서 과업이며 완료된 bootstrap 과업을 재실행하지 않는다. 헌장·설치본·원본 패키지는 수정하지 않는다. 기존 Git index도 건드리지 않는다. 원개발자에게 전송·커밋·원격 발행하지 않는다.

이번 자체 검증은 명세와 현행 설치 근거의 대조다. 독립 검증은 요청되지 않았고 첫 설치의 의무는 기존 과업에서 충족했으므로 반복하지 않는다. 필수 기준은 관련 checklist에 고정하며, 권장 기능의 미채택을 실패로 판정하는 문구가 없는지 의미 검토한다.

## 복구·재개

기존 파일 충돌 시 덮어쓰지 않고 확인한다. 중단되면 같은 task_id와 이 문서 경로를 유지하고 미완료 항목부터 재개한다. 원시 근거는 `temp/wiki-desk-export/`에 둔다.
