# 하네스규칙

## 아우터 하네스와 이너 하네스

val_agent가 배포하는 것은 **아우터 하네스**다. 사람이 설계한 헌장(`rules/`), 스킬(`skills/`), 과업 문서 체계(`docs/`), 위키 계약이 여기에 속한다. 그 위에서 파일을 읽고 명령을 실행하는 **이너 하네스**(Codex CLI, Claude Code 등 Agentic CLI)는 교체할 수 있는 실행 도구다. 이너 하네스가 바뀌어도 규칙, 승인, 과업 상태, 작업 이력은 그대로 유지된다.

정본은 하네스 중립 경로에만 둔다. 하네스별 경로에는 진입 파일, 발견용 링크, 하네스 고유 설정만 둔다. 정본 내용을 하네스별로 복제하지 않는다.

| 이음매 | 정본 | Codex 어댑터 | Claude Code 어댑터 |
|---|---|---|---|
| 진입 지침 | `AGENTS.md` | `AGENTS.md`를 자동으로 읽는다(import 문법 없음) | `CLAUDE.md` = `@AGENTS.md` |
| 헌장 | `rules/*.md` | AGENTS.md의 지시에 따라 읽는다 | 같음 |
| 스킬 | `skills/<name>/` | `.agents/skills/<name>` 디렉터리 심볼릭 링크 | `.claude/skills/<name>` 디렉터리 심볼릭 링크 |
| 스킬 호출 | SKILL.md의 `name`·`description` | `$name`, `/skills`, 자동 선택 | `/name`, 자동 선택 |
| 하네스 고유 메타데이터 | 없음 | `skills/<name>/agents/openai.yaml` | 없음 |
| 권한·자율도 | 공통 금지선(아래) | `.codex/config.toml`(로컬, Git 제외), 사용자 설정 | `.claude/settings.json`(금지선만 추적), `.claude/settings.local.json`(로컬 allow 목록), 자율 모드는 사용자 설정이나 실행 플래그 |
| 로컬 훅 | 스킬의 참조 문서에 설치 예시만 둔다 | `.codex/hooks.json`(로컬, Git 제외) | `.claude/settings.local.json`(로컬, Git 제외) |
| 서브에이전트 | 스킬은 "호스트의 서브에이전트 기능"이라는 의도만 적는다 | 내장 서브에이전트, `.codex/agents/*.toml` | Agent 도구, `.claude/agents/*.md` |
| headless 실행 | worker-agent-control의 provider별 문법 | `codex exec --json` | `claude -p --output-format json\|stream-json` |

스킬과 헌장에는 "서브에이전트에 맡긴다", "명령을 워커 루트에서 실행한다"처럼 의도만 적는다. 특정 하네스의 도구 이름이 필요하면 지원하는 하네스의 예시를 함께 적는다. 실제 CLI 문법은 해당 스킬의 provider 구현과 참조 문서에만 둔다. 새 하네스를 붙일 때는 이 표에 어댑터를 추가하고, 스킬 본문은 다시 쓰지 않는다.

## 역할은 호출 형태로 정한다

- 사용자가 띄운 대화 세션에서 동작하면 val_agent는 **오케스트레이터**다. 오케스트레이터는 Codex든 Claude Code든 맡을 수 있다.
- 다른 에이전트가 headless로 val_agent를 호출하면 val_agent는 그 호출자의 **워커**다. 이때는 호출자의 요청과 승인 범위를 따른다. 산출물은 과업 문서와 실행 근거로 회수할 수 있어야 한다. 워커 모드의 구체적인 receipt 계약은 실제 호출자가 생길 때 정한다.
- 오케스트레이터 하네스와 그가 부리는 워커 CLI는 서로 독립이다. 같은 종류여도 된다.

## 실행자 기록과 대체 금지

- 모든 실행에는 실제 실행자(하네스, 모델, native 세션)를 기록한다. 요청된 실행자가 명시돼 있었다면 그것도 함께 기록한다.
- 명시된 실행자를 다른 하네스나 모델로 조용히 대체하지 않는다. 승인을 받아 대체했더라도 그 성공을 원래 요청한 실행자의 성공으로 집계하지 않는다.
- 프로세스 exit 0이나 에이전트의 완료 선언은 업무 완료의 증거가 아니다. 검증과 수용은 [작업수행규칙](workflow.md)을 따른다.

## 하네스 전환과 인계

- 하네스를 전환해도 과업을 초기화하지 않는다. 기존 승인, 과업 문서, 진행 상태를 그대로 이어받는다. 하네스 전환은 새 루프를 여는 사유가 아니다. 새 루프는 [작업수행규칙](workflow.md)에 따라 사용자의 요청이나 승인으로만 연다.
- native 세션 ID는 하네스 사이에서 재사용하지 않는다. 인계는 과업 문서(interview·plan·devlog·checklist)와 원시 근거 경로로 한다. 2계층 과업은 캠페인 인스턴스도 함께 넘긴다. 이어받은 하네스는 devlog에 자기 실행자 정보와 재개 지점을 남긴다.
- 오케스트레이터에서 한도, 인증 만료, 미도달 같은 실행자 측 실패가 나면 멈춘 지점과 부분 산출물을 보존하고 사용자에게 보고한다. 다른 하네스로의 전환은 사용자가 확인한 뒤에만 한다. 워커 쪽의 자동 회전은 해당 워커 프로젝트의 계약을 따른다.
- 한 하네스가 같은 작업 트리에 쓰고 있는 동안 다른 하네스는 그 트리에 쓰지 않는다. 열려 있더라도 쓰지 않는 세션(예: 한도 소진으로 멈춘 세션)은 사용자가 그렇게 확인한 경우에 한해 예외로 둔다. 동시 작업이 필요하면 분리된 작업 트리나 범위를 과업 plan에 정한다.

## 권한

자율도(승인 모드, allow 목록, 샌드박스 수준)는 머신과 하네스별 설정이며 저장소의 정본이 아니다. 하네스마다 설정 문법과 세분도가 다르므로 동등성을 주장하지 않는다. 에이전트가 모든 항목을 조정할 수는 없으며, 사용자가 추가로 조정하는 것을 전제로 한다.

하네스와 관계없이 다음 행동에는 사용자 승인이 필요하다. 각 하네스 설정에서 가능한 범위로 막거나 확인을 요구하되, 설정이 없다는 사실을 허가로 해석하지 않는다.

- 원격 발행: `git push`와 공개 저장소 반영.
- 이력 파괴: force push, `git reset --hard`, `git clean -f`, 이력 재작성, 브랜치 삭제.
- 작업 공간 밖 쓰기: 워커 저장소, 사용자 전역 설정(`~/.codex`, `~/.claude`), 인증 정보.

Claude Code는 `.claude/settings.json`과 `.claude/settings.local.json`에 적힌 `bypassPermissions`·`auto` 모드를 무시한다. 이 모드는 사용자 설정(`~/.claude/settings.json`)이나 실행 플래그(`--permission-mode`)로만 켤 수 있다. 따라서 추적하는 `.claude/settings.json`에는 위 금지선의 deny/ask 규칙만 둔다. 로컬 allow 목록은 `.claude/settings.local.json`에, 자율 모드는 사용자 설정이나 실행 플래그에 둔다. Codex의 프로젝트 `.codex/config.toml`은 trusted 프로젝트에서만 적용되며, 이 저장소에서는 로컬 파일로 둔다.

스킬이 외부 LLM을 부를 때 쓰는 API 키와 Judge 프로필은 프로젝트 루트의 `envs/`에 둔다. 키는 `envs/.env`에, 프로필은 `envs/<name>_profile.yaml`(model과 생성 설정, 키 없음)에 둔다. `envs/`에서는 예시(`envs/.env.example`, `envs/profile.example.yaml`)만 추적하고, 실제 키·프로필 파일은 Git·공개본에 넣지 않는다. 이미 설정된 프로세스 환경변수가 파일보다 먼저다. 키 값을 문서·로그·설정·응답에 옮겨 적지 않는다.

이런 스킬은 자기 `config.yaml`에 `provider`와 `judge_profile`(envs 안의 파일 이름) 두 knob을 두고, 스킬 안의 어댑터가 공용 프로필을 자기 런타임의 설정으로 바꾼다. 런타임이 받지 못하는 프로필 항목은 적용하지 않았다고 보고하며, 조용히 버리거나 다른 값으로 대체하지 않는다. 스킬은 프로젝트 루트를 자기 설치 위치로 정해 `envs/`를 찾고, 다른 위치는 명시 인자로 받는다. 키·프로필을 새로 만들거나 바꾸는 것은 사용자가 한다.

외부 서비스와 별도 의존성이 필요한 스킬은 SKILL.md frontmatter에 `metadata.activation: opt-in`을 두고 비활성 상태로 배포한다. 정본 폴더는 `skills/`에 있지만 발견 링크와 활성 config는 없다. 받은 시스템의 사용자가 `python3 scripts/skill_activation.py enable <skill> --apply`로 켜며, 이 링크는 로컬 작업물로 추적하지 않는다.

로컬 훅(예: 캠페인의 종료 훅)은 하네스별 로컬 설정 파일에 둘 수 있다. 추적하는 설정에는 훅을 두지 않는다. 저장소를 받은 사람의 세션이 뜻하지 않게 막히지 않게 하기 위해서다.

## 검사

`python3 scripts/check_harness_adapters.py`는 진입 파일과 스킬 링크의 연결, 하네스 고정 문구, 옛 정본 경로의 잔존을 검사한다. 정적 검사 통과는 각 하네스가 실제로 인식한다는 증거가 아니다. 실제 인식은 하네스별 새 세션에서 따로 확인하고 기록한다.

`python3 scripts/check_campaign.py`는 캠페인의 틀과 인스턴스가 형식을 지키는지 읽기 전용으로 검사한다. 이 검사는 선언한 검사 명령을 실행하지 않으며, 통과가 항목의 결과가 옳다는 증거는 아니다. 선언한 검사를 실행하고 그 결과를 기록하는 것은 progress-monitor 스킬의 실행기다.
