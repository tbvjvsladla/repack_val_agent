# 검증 묶음과 gate

## 묶음을 짜는 법

- 검증 묶음은 **함께 바뀌고 같은 검사로 확인되는 cell**의 모음이다. cell의 `group`이 구성원을 정하고, 묶음의 `checks`가 gate에서 돌릴 검사다.
- 빌드 구성이 갈리는 검사는 같은 구성끼리 모은다. 구성이 다른 검사를 한 묶음에 섞으면 gate마다 빌드를 여러 번 다시 한다.
- 넓은 검사가 좁은 검사를 포함하면 넓은 검사의 `covers`에 좁은 검사의 id를 적는다. 넓은 검사의 `inputs`는 좁은 검사의 `inputs`를 모두 포함해야 한다. 덮음 선언이 옳은지는 선언한 사람의 책임이다. 좁은 검사의 입력이 커밋되지 않은 상태에서 돌린 넓은 검사는 그 검사를 덮지 않는다.
- 입력 선언(`inputs`)은 넓게 잡는다. 빠뜨린 입력은 잘못된 재사용이 되고, 넓은 입력은 재실행 한 번이 될 뿐이다.
- 단계의 증명 명령(`proof.check`)은 가벼운 자기 확인(빌드, 정적 확인)으로 한다. 묶음의 검사를 여기서 미리 돌리지 않는다.
- 묶음은 수행 중에 다시 짤 수 있다([direction.md](direction.md)). 강제 재실행과 실행 실패의 횟수는 검사를, 검토 회차는 cell을 따라가므로 묶음을 옮겨도 0으로 돌아가지 않는다.

## gate를 돌리는 때

- `gate run <group>`의 조건: gate가 `pending`이나 `failed`다. 취소되지 않은 구성원이 하나 이상이고 모두 `open`이며 `change`가 `done`이다. 아니면 거절한다(종료 1).
- gate를 돌리기 전에 대상의 변경을 커밋한다. 커밋되지 않은 입력으로 돌린 결과는 다시 쓸 수 없다(아래 규칙 1).
- gate가 통과하면 그때의 구성원을 gate 기록에 적고, 검토 표시가 없는 구성원을 닫는다. 검토 표시가 있는 구성원은 새 맥락 검토 뒤에 `cell close`로 닫는다.
- `passed`인 gate는 `gate reopen` 없이 다시 돌리지 않는다.
- 같은 gate를 두 곳에서 동시에 돌리지 않는다. 실행기가 두 번째 실행을 거절한다. 실행 중인 gate는 사람에게 넘길 수 없다.
- gate가 도는 동안 구성원이 다시 열려 고쳐졌으면 그 실행은 통과로 치지 않는다(`pending`). 다시 돌린다.

## 검사 하나를 돌리는 규칙

**자기 판정**은 지금의 키와 같은 키를 가진, 무효가 아닌 영수증 가운데 가장 늦은 `PASS` 또는 `FAIL`이다. 같은 키에 `PASS`와 `FAIL`이 함께 있으면 가장 늦은 것이 정한다.

**키**는 명령, 실행 폴더, 기준(`expect`), 선언한 환경 변수의 값, 입력의 Git 객체 ID, 호스트, 환경 확인 명령(`env_probe`)의 출력이다. 실행자는 영수증에 적지만 키에 넣지 않는다.

위에서부터 처음 맞는 줄을 따른다.

| 순서 | 조건 | 결과 |
|---|---|---|
| 1 | `inputs`가 비었다. 입력 중 커밋되지 않은 것(수정됨, 추적 안 됨)이 있다. 대상이 Git 저장소가 아니다. 입력 중 Git 객체 ID를 얻을 수 없는 것이 있다 | 실행한다. 이 영수증은 다시 쓰지 않는다 |
| 2 | `--force`가 있다 | 상한 안이면 사유를 적고 실행한다(`forced`). 상한에 닿았으면 사람에게 넘기고 그 실행 전체를 거절한다. gate의 상태는 바뀌지 않는다 |
| 3 | 자기 판정이 `PASS`다 | 실행하지 않는다 (`reused`) |
| 4 | 자기 판정이 `FAIL`이다 | 거절한다 (`refused`). 입력을 고치거나 `--force`가 필요하다 |
| 5 | 같은 키의 실행이 거듭 실패(`ERROR`)해 상한에 닿았다 | 거절하고 사람에게 넘긴다. gate는 `waiting`이 된다 |
| 6 | 이 검사를 덮는 검사의 자기 판정이 `PASS`이고, 그 영수증에 적힌 이 검사의 입력이 지금과 같다 | 실행하지 않는다 (`covered`) |
| 7 | 그 밖 | 실행한다 (`ran`) |

- **건너뛴 것은 통과가 아니다.** `reused`는 재사용한 영수증을, `covered`는 덮은 영수증을 가리킨다. gate 기록과 보고에는 실행한 것과 건너뛴 것을 구분해 적는다.
- **결과의 구분.** 명령이 끝까지 돌았고 종료 코드가 0이며 출력에 `expect`가 있으면 `PASS`, 끝까지 돌았으나 그렇지 않으면 `FAIL`이다. 시간 초과, 실행 파일 없음(종료 코드 126·127), 신호로 죽음(종료 코드 129~192 포함. 셸이 신호로 죽은 명령에 주는 값이다), 프로세스를 띄우지 못함은 `ERROR`(실행의 실패)다. `ERROR`는 검사의 판정이 아니다.
- **실행의 실패는 다시 돌릴 수 있다.** `exec_retries`가 2이면 같은 입력에서 모두 3회까지 실행하고 4번째 요청을 거절한다.
- **자기 판정이 덮음보다 앞선다.** 좁은 검사가 자기 키에서 `FAIL`했으면 넓은 검사의 통과로 덮지 않는다.
- **덮음은 덮이는 검사의 명령을 보지 않는다.** 빌드 구성이 조금 달라도 넓은 검사의 통과로 닫는다. 사용자가 받아들인 위험이다. 환경(호스트, `env_probe`)은 덮는 검사의 키에 들어 있다.
- **검사 명령은 실패를 종료 코드로 전하게 쓴다.** 여러 명령을 이으면 `&&`나 `set -e -o pipefail`을 쓴다. `;`나 파이프 뒤에 가려진 실패와 신호는 실행기가 알 수 없다. 종료 코드 129~192는 신호로 죽음으로 읽으므로, 실패 수를 종료 코드로 내는 검사는 그 범위를 쓰지 않게 한다.
- **검사가 도는 동안 그 입력이 바뀌면** 그 결과는 다시 쓰지 않는다. 어느 입력을 읽었는지 알 수 없기 때문이다.
- **Git이 무시하는 파일**은 "커밋되지 않은 입력"이 아니다.
- **입력은 대상 저장소가 커밋한 파일이나 폴더의 경로로 적는다.** glob, 없는 경로, Git이 무시하는 경로, 다른 저장소 안에 `git init` 없이 둔 폴더는 객체 ID를 얻을 수 없다. 그런 입력을 가진 검사는 매번 실행한다. 심볼릭 링크는 입력으로 적지 않는다. 링크가 가리키는 경로를 적는다(링크의 객체 ID는 가리키는 내용이 바뀌어도 그대로다).
- **gate 안의 순서.** 덮는 검사를 덮이는 검사보다 먼저 본다. 한 검사가 실패하거나 거절돼도 나머지 검사를 끝까지 본다. 원인을 가르는 데 쓴다.
- **gate의 결과.** 위에서부터 처음 맞는 것이다. 실행 실패 상한에 닿은 검사가 있으면 `waiting`. `FAIL`이나 규칙 4의 거절이 있으면 `failed`. 상한 전의 `ERROR`가 있으면 `pending`(결론이 나지 않았다). 그 밖은 `passed`.

## 강제 재실행

- 결과를 의심할 근거가 있을 때만 `--force <검사> --reason <사유>`를 쓴다. 사유가 사건에 남는다.
- 상한은 검사당 `forced_reruns_per_check`회, 캠페인 전체 `forced_reruns_total`회다. 상한에 닿으면 실행기가 사람에게 넘기는 사건을 쓰고 거절한다. 답이 올 때까지 그 검사의 `--force`만 막힌다. 입력을 고쳐 다시 돌리는 길은 열려 있다.
- 같은 입력에서 통과가 실패로, 실패가 통과로 바뀌면 검사가 입력 밖의 것에 기대고 있다는 뜻이다. 빠진 입력을 찾아 선언에 더하고 `check invalidate`를 한다.

## 무효와 STALE

- **무효**: `check invalidate <검사> --reason`은 그 시각보다 앞선 그 검사의 영수증과, 다른 영수증에 든 그 검사의 덮음을 쓰지 않게 한다. 빠진 입력을 찾았거나 검사를 고쳤을 때 쓴다.
- **`STALE`은 표시다.** `status`는 통과한 gate가 가리키는 영수증의 입력이 지금과 다르면 그 검사와 gate를 `STALE`로 보인다. gate의 상태는 바꾸지 않는다. `STALE`은 커밋된 입력을 견준다. 커밋하지 않은 변경이 있는 검사는 `uncommitted_checks`에 따로 보인다.
- **`STALE`인 통과를 자동으로 다시 돌리지 않는다.** 다른 묶음의 변경이 이 묶음의 입력을 건드리면 `STALE`이 된다. 묶음 사이의 상호작용은 마지막 전체 검증이 한 번 잡는다. 그 전에 확인해야 한다고 판단하면 `gate reopen`으로 다시 연다.

## gate가 실패했을 때

1. gate 기록의 검사별 결과와 로그를 읽고 원인을 가른다: 어느 cell의 변경인가, 검사 자체의 결함인가, 구성원 사이의 상호작용인가.
2. 판정을 `event`로 남긴다.
3. cell의 변경이 원인이면 그 cell을 `cell reopen`으로 다시 연다. `change`가 `pending`으로 돌아가고 gate도 `pending`이 된다. 고쳐 커밋한 뒤 다시 `gate run`을 한다. 입력이 바뀌었으므로 검사가 다시 돈다.
4. 검사가 고장 났으면 선언을 고치고 `event`로 남긴다. 검사를 지우거나 기준을 낮추는 일은 사람에게 넘긴다([direction.md](direction.md)).
5. 같은 입력으로 다시 돌리지 않는다. 실행기가 거절하고, 종료 훅이 그것을 정체로 본다.

## 마지막 전체 검증

- `final run`은 선언의 `final.checks`를 돌린다. gate에서 난 영수증과 덮음을 쓰지 않는다. 마지막 전체 검증 자신의 결과에는 같은 규칙을 적용한다: 통과한 뒤 입력이 그대로면 다시 돌리지 않고(`already-passed`), 실패한 뒤 입력이 그대로면 거절한다.
- 돌릴 수 있는 때는 모든 묶음이 "통과", "멈춤", "취소"일 때다. "멈춤"인 묶음의 gate가 통과하지 않았으면 그 검사는 gate에서 확인되지 않은 채다. 그 사실을 과업의 checklist에 그대로 적는다.
- 통과한 뒤에 어떤 gate가 다시 열리면 마지막 전체 검증도 `pending`으로 돌아간다.
- 실패하면 다시 돌리지 않는다. 원인을 가려 그 묶음의 cell을 `cell reopen`으로 다시 연다.

## 상태와 전이

**cell**

| 상태 | 뜻 | 들어오는 길 | 나가는 길 |
|---|---|---|---|
| `open` | 진행 중 | 처음, `cell add`, `cell reopen`, `gate reopen`, `cell resume`, `hitl answer` | 아래 넷 |
| `closed` | 닫힘 | gate 통과(검토 표시 없음), `cell close`(검토 표시 있음) | `gate reopen`, `cell reopen` |
| `cancelled` | 취소됨 | `cell cancel` | 없음 |
| `stopped` | 사람에게 넘김(정체, 검토 상한) | `cell stop`, `review record`(상한 회차에도 차단 지적이 남음) | `cell resume`(사용자 승인) |
| `waiting` | 사람의 답을 기다림 | `hitl open --cell` | `hitl answer` |

**gate**

| 상태 | 들어오는 길 | 나가는 길 |
|---|---|---|
| `pending` | 처음, `gate reopen`, `cell reopen`, 구성원의 추가·이동, `hitl answer`, 상한 전의 `ERROR`로 끝난 `gate run` | `gate run`, `hitl open --group` |
| `passed` | 모든 검사가 실행해 `PASS`이거나 `reused`·`covered` | `gate reopen`, `cell reopen`, 구성원의 추가·이동 |
| `failed` | 하나라도 `FAIL`이거나 규칙 4의 거절 | `gate run`, `cell reopen`, `hitl open --group` |
| `waiting` | `pending`이나 `failed`에서만: 실행 실패 상한, `hitl open --group` | `hitl answer` |

`passed`인 gate는 `waiting`이 되지 않는다. 통과한 묶음에서 사람의 결정이 필요하면 `hitl open --cell`을 쓴다.

**묶음** (저장하지 않고 위 둘에서 낸다. 위에서부터 처음 맞는 줄이다)

| 상태 | 조건 |
|---|---|
| 취소 | 구성원이 없거나 모두 `cancelled`다 |
| 멈춤 | `stopped`인 구성원이 있다 |
| 기다림 | gate가 `waiting`이거나 `waiting`인 구성원이 있다 |
| 통과 | gate가 `passed`다 |
| 실패 | gate가 `failed`다 |
| 진행 | 그 밖 |

구성원이 멈추면 그 묶음도 멈춘다. 다른 묶음은 계속한다.

**불변식.** `closed`인 cell의 묶음은 gate가 `passed`이고 gate 기록의 구성원에 그 cell이 있다.

**그 밖의 규칙**

- `phase start`: cell이 `open`이고 앞 단계가 `done`이다. `change`를 시작할 때 `needs`의 cell이 같은 묶음이면 그 `change`가 `done`, 다른 묶음이면 그 묶음의 gate가 `passed`여야 한다. 취소된 cell에 대한 `needs`는 채워진 것으로 본다.
- `gate reopen`: gate를 `pending`으로, 닫힌 구성원을 `open`으로 돌린다. 단계의 상태는 그대로다. 다시 `gate run`하면 닫힌다.
- `cell reopen`: `change`가 `done`인 cell의 `change`를 `pending`으로 돌린다. gate가 `passed`나 `failed`면 `gate reopen`과 같은 일을 한다. 커밋은 건드리지 않는다.
- 통과한 묶음에 구성원이 들어오거나 나가면 gate가 다시 열린다. `closed`인 cell은 옮길 수 없다.
- `cell close`: 검토 표시가 있고, cell이 `open`이며, gate가 `passed`이고, 마지막 gate 통과보다 뒤의 가장 늦은 검토가 실행됐고 `clean`이다.
- `review record`: 회차가 상한 이상이고 차단 지적이 남았으면 그 cell이 `stopped`가 된다.
