# 방향 조정과 사람에게 넘김

plan은 큰 분류(범위, 검사와 기준, 검토 표시, 상한)만 정한다. cell의 분할과 묶음은 수행 중에 메인 에이전트가 정한다. 수행하다 보면 조정은 당연히 생긴다. 조정은 자주, 가볍게 하고 반드시 기록한다.

## 스스로 하는 것과 넘기는 것

| 스스로 한다 (사건 기록에 남긴다) | 사람에게 넘긴다 |
|---|---|
| cell을 나누거나 새 묶음을 만든다 | 목표나 수용 기준을 바꾼다 |
| 선언한 범위 안에서 새 cell을 만든다(수에 상한) | 범위 밖의 작업 |
| 필요 없어진 cell을 취소한다 | 검사 기준을 낮춘다(검사 삭제, 기대값 완화) |
| 접근 방법을 바꾼다 | 상한이나 검토 표시를 바꾼다 |
| | 권한 확대, 원격 발행, 파괴적 변경 |

## 스스로 하는 조정

- **새 cell**: `cell add <spec.json>`. 입력은 `cell`, `goal`, `group`, `parent`, `needs`, `reason`과 단계별 증명(`prepare`, `change`의 `check`·`expect`)이다. 선언에 없는 묶음이면 `group_checks`(선언에 있는 검사의 id)로 새 묶음을 함께 만든다.
  - 스스로 만드는 cell의 수는 `auto_cells`까지다. 상한에 닿으면 실행기가 거절하고 사람에게 넘기는 사건을 쓴다.
  - 다른 cell에서 갈라져 나온 cell은 `parent`를 적는다. 부모의 검토 표시와 회차를 물려받는다. 부모가 없는 새 cell은 검토 표시가 없다. 표시가 필요해 보이면 사람에게 넘긴다. 수행 중의 판단으로 표시를 더하지 않는다.
- **취소**: `cell cancel <cell> --reason`. 지우지 않고 `cancelled`와 사유를 남긴다. 멈췄거나 답을 기다리는 cell은 스스로 취소하지 못한다. 취소해도 묶음의 검사는 남는다. 취소한 cell의 대상을 다시 만들 때는 `parent`로 그 cell을 적는다. 검토 회차를 되돌리는 길로 쓰지 않는다.
- **묶음 재편**: `cell move <cell> <group> --reason`. 없는 묶음이면 `--checks`로 만든다. 통과한 묶음에 구성원이 들어오거나 나가면 그 gate가 다시 열린다. 닫힌 cell은 옮길 수 없다. 먼저 `gate reopen`을 한다.
- **접근 방법의 변경**: `event`로 `direction` 사건을 남기고 `cell.md`의 "막다른 길"과 "남은 계획"을 고쳐 쓴다.
- 검사를 더하거나 고장 난 검사를 고치는 것은 선언을 고치고 `event`로 남긴다. 검사를 지우거나 기준을 느슨하게 하는 명령은 없다. 그것은 사람에게 넘긴다.

## 후보가 둘 이상일 때

방향을 조정할 때 후보가 둘 이상이면 종이로 고르지 않는다. 실제로 실행해 비교한다.

1. `explore open --cell <cell> --reason <사유>`로 연다. 돌려받은 id를 쓴다.
2. 후보마다 대상의 별도 작업 트리에서 실제로 바꾸고 커밋한다. 작업 트리는 대상 저장소 밖의 폴더에 둔다.
3. 그 묶음의 검사를 `check run <검사> --explore <id> --target <작업 트리>`로 돌린다. 기준선(고치기 전의 대상)도 같은 명령으로 돌린다. 결과는 영수증으로 남는다.
4. 영수증과 로그로 비교해 고른다.
5. `explore close <id> --selected <후보> --ref <근거의 위치>`로 고른 결과를 남긴다.
6. 고른 후보를 대상에 그대로 들여온다. 입력의 Git 객체 ID가 같으므로 gate가 그 영수증을 재사용한다.

- 한 번의 탐색에서 후보의 작업 트리는 `explore_candidates`개까지, 캠페인 전체의 탐색은 `explore_rounds`번까지다. 실행기가 막는다.
- 더 좋은 개선안은 깊게 탐색하고, 검증은 쓸데없이 돌리지 않는다. 비교의 잣대는 그 묶음이 선언한 검사다. 탐색을 위해 새 검사를 지어내지 않는다.
- 후보를 관리하고 고르는 도구는 과업의 plan이 정한다. 이 스킬은 "후보마다 선언한 검사를 실행기로 돌려 비교한다"까지만 정한다.
- 고른 결과는 실험 안의 비교이며 수용이 아니다.

## 사람에게 넘기는 법

- `hitl open --cell <cell> --kind <종류> --question <물음>`. 그 cell이 `waiting`이 된다. 묶음의 gate에 대한 결정이면 `--group`, 마지막 전체 검증이면 `--final`을 쓴다. 통과한 gate에는 `--group`을 쓸 수 없다. 그때는 `--cell`을 쓴다. 실행 중인 gate에도 쓸 수 없다. 끝난 뒤에 넘긴다.
- 물음은 사용자가 그것만 읽고 답할 수 있게 쓴다: 무엇을 정해야 하는가, 고를 수 있는 길, 각 길의 결과.
- **사람에게 넘기면 그 cell만 기다린다. 시한이 없다.** 다른 cell을 계속한다. 시간이 지났다는 이유로 스스로 정하지 않는다.
- 스스로 풀 수 없는 일을 붙들지 않는다. 넘기고 다음 일로 간다.
- 기다리는 결정은 `status`의 `waiting`에 있고 브리핑의 맨 위에 둔다.
- 사용자가 답하면 `hitl answer <id> --ref <근거>`로 기록한다. 근거는 그 답이 적힌 곳(과업 문서의 위치)이다. 상한에 걸려 넘긴 결정에 사용자가 한 번 더 허용하면 `--allow`를 붙인다. 그 상한이 한 번 늘어난다.
- 실행기가 스스로 넘기는 것: 강제 재실행의 상한(`forced-rerun-cap`), 실행 실패의 상한(`exec-retry-cap`), 스스로 만드는 cell의 상한(`auto-cell-cap`).
- 멈춘 cell(`stopped`)은 사용자의 승인이 있어야 다시 연다: `cell resume <cell> --ref <근거>`.
