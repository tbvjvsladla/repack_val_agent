# 원본 의미와 변환 경계

## 관찰 동작

구현·테스트·호출부에서 해당 계약을 확인한다. 단순 작업에는 필요한 부분만 기록한다.

| 경계 | 확인할 의미 |
|---|---|
| API/CLI/프로토콜 | 공개 이름·인자·기본값·stdin/stdout/stderr·종료 코드·직렬화 키/순서/표현 |
| 데이터 | 정수 범위·overflow·반올림·문자/바이트·Unicode·개행·공백·빈 값과 누락의 차이 |
| 오류 | 정상과 실패, 오류 종류·내용·시점, 실패 전 부분 부작용·복구 |
| 순서·상태 | 삽입 순서·정렬 동률·중복·동시성·취소·재시도·파일/프로세스 수명 |

원본의 버그·모호함을 보존하고 표시한다. 이해하지 못한 특이 동작을 조용히 수정하지 않는다. 호출 범위가 확인되지 않았는데 ‘드문 입력’이라는 이유로 Unicode·큰 정수·오류 동작을 바꾸지 않는다. 재현할 수 없는 의미가 있으면 차이와 필요한 결정을 반환한다.

## 언어 의미의 함정

- Python: 임의 정밀도 정수→고정폭 변환 전 입력 범위를 확인한다. dict 삽입 순서, bool/int 관계, Unicode와 바이트, 예외·빈 값·누락을 구별한다.
- JavaScript/TypeScript: number 정밀도·NaN, null/undefined/누락, 문자열의 UTF-16 기준 처리, 객체 키 순서, 비동기 실패·취소를 확인한다.
- C/C++: signed/unsigned·overflow/미정의 동작, 포인터·자원 소유권, NUL 문자열·반환 코드·out parameter를 확인한다. 미정의 동작을 재현하려고 unsafe를 만들지 않는다. 보존 불가능한 경계는 보고한다.
- 다른 언어: 정수·문자열·컨테이너·오류·메모리·동시성 의미를 조사한다. 위 목록을 지원 보장이나 입력 언어 제한으로 해석하지 않는다.

의미가 동등한 Rust 표현을 선택한다. 런타임 전체를 복제하거나 근거 없는 호환 계층을 추가하지 않는다. 필요한 호환성을 구현할 수 없다면 지원 범위를 줄여 성공 처리하지 않는다.

## 테스트 대응과 연결

원본 적용 테스트마다 Rust 테스트나 같은 계약을 확인하는 대응 검사를 연결한다. 테스트가 없으면 관측한 정상·오류·경계 동작을 특성화한다. 관측할 수 없는 결과를 새 구현의 출력으로 정답화하지 않는다.

원본이 실행 가능하면 같은 입력으로 비교한다. 바이트 보존 계약이면 실제 출력도 비교한다. 시간·임의값·순서가 비결정적이면 계약과 허용 비교 방법을 먼저 확인한다. 미수집·빈 실행은 테스트 통과가 아니다.

CLI·crate·FFI·원 언어 모듈 wrapper는 다른 산출물이다. Rust 로직만으로 기존 import가 연결됐다고 가정하지 않는다. 연결 코드는 과업 입력에 명시된 파일·호출 계약·환경만 작성하며 필요한 인자·반환·오류·소유권 대응과 자체검사를 포함한다.

연결이 미지정됐거나 환경 정보가 없으면 아직 연결되지 않은 경계를 반환한다. 임의 바인딩·런타임 설치·호출자 교체로 해결하지 않는다. 즉시 대체물이 요구됐는데 연결을 충족하지 못했다면 전체 변환을 `COMPLETE`로 표시하지 않는다.
