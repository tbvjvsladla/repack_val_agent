# Rust Repack

기존 동작을 보존하는 Rust 구현과 확인 가능한 실행 근거를 반환한다. 단순 구문 번역이나 주석 감축을 목표로 삼지 않는다. **의미 파악 → 이름·타입 → 책임·흐름 → 필요한 문서화 → 자체검사·수정** 순으로 수행하되 이미 명확한 코드를 불필요하게 바꾸지 않는다.

## 입력과 경계

실제 적용 지침과 대상 파일·호출부·테스트를 읽고 다음을 확정한다. 확인 가능한 사항을 다시 질문하지 않는다.

- 원본 범위, Rust 출력 경로와 crate/library/CLI 등 산출 형태, 수정 허용 경로.
- 보존할 호출·입출력·오류·부작용 계약과 지원 입력 범위.
- 대상의 toolchain/MSRV·edition·target·feature, 허용 의존성과 실행 환경.
- 원본 실행·테스트 명령과 데이터. 연결 코드가 명시됐다면 범위·호출 계약·지원 환경.

과업 지정과 대상 저장소 규칙으로 해결되지 않는 중요한 누락만 확인한다. 언어·규모에 관계없이 항상 변환 가능하다고 약속하지 않는다. 런타임 의미나 외부 계약을 재현할 수 없다면 임의 축소하지 말고 누락·대안을 반환한다.

Rust 버전·비동기 런타임·바인딩 기술을 임의 고정하지 않는다. 의존성 추가는 허용 범위에서만 한다. toolchain 설치·전역 설정·호스트 등록·배포·원본 삭제를 변환 권한에서 추론하지 않는다. 최소 연결 코드(shim)는 **과업 입력에 명시된 경우만** 작성한다. 미지정 연결이 필요하면 연결되지 않은 경계와 필요한 결정을 보고한다.

## 동작을 먼저 고정

[의미·호환성](references/compatibility.md)을 읽고 원본의 정상·실패·경계 동작과 호출자를 확인한다. 원본 주석은 조사 단서이지 정답이 아니다.

기존 적용 테스트를 Rust로 이식하고 원본과 대응시킨다. 테스트가 없으면 확인한 원본 동작을 특성화 테스트로 고정한다. 원본이 실행 가능하면 같은 입력의 원본·변환 결과를 비교한다. 원본 테스트·정답·지원 범위를 새 구현에 유리하게 바꾸지 않는다. 실행 불가와 모르는 동작을 검증된 사실로 채우지 않는다.

외부 이름·직렬화 키·CLI 옵션·종료 코드·출력 바이트·오류 동작을 보존한다. 드문 입력, 알려진 버그, 불편한 계약도 동의 없이 바꾸지 않는다. 안전성 문제 등으로 보존이 불가능하면 해당 경계를 미완료로 보고한다.

## Rust로 재구성

변환 전에 [클린코드 기준](references/clean-code.md)을 읽는다. 내부 이름으로 역할·단위·조건·상태를 표현하고 Rust 관례를 따른다. 타입과 소유권으로 실제 불변조건을 표현하되 모든 값에 새 타입을 만들지 않는다. 혼재한 책임·숨은 상태 변경·불필요한 중첩을 개선하고 실행 순서·오류 시점·자원과 락 수명을 보존한다.

이름과 구조를 개선한 뒤에도 남는 계약·근거를 간결하게 문서화한다. 모호한 설계에 그럴듯한 설명을 붙이지 않는다. 변환 범위의 구체적인 혼동·중복·누락을 해결하면 정리를 끝낸다. 주변 코드까지 확장하거나 더 좋은 이름을 끝없이 탐색하지 않는다.

## 검사·수정·반환

[자체검사와 도구](references/verification.md)를 읽고 대상에 맞는 fmt·build·Clippy·테스트를 수행한다. 해당되는 기존 테스트는 이식·통과해야 한다. 실패하면 승인 범위의 산출물을 고치고 영향을 받은 검사만 재실행한다. lint를 숨기거나 정답·필수 기준을 낮춰 통과시키지 않는다.

필수 환경 부재는 `NOT_RUN`, 실행한 검사 실패는 `FAIL`로 구분하며 어느 쪽도 완료로 반환하지 않는다. 같은 실패가 새 근거 없이 반복되거나 필요한 권한·정보가 없으면 부분 산출물을 보존하고 멈춘다.

최종 응답 또는 과업이 지정한 변환 기록에 다음을 남긴다. 별도 형식이 없고 파일 인계가 필요한 경우 `PORTING.md`를 사용한다.

- `COMPLETE` 또는 `INCOMPLETE`: 이번 변환 범위와 적용 필수검사에 대한 상태.
- 출력 경로, 원본→Rust API·테스트 대응, 내부 의미·타입·책임 개선의 주요 근거.
- 보존한 외부 계약·특이 동작, 명시된 연결 코드 범위와 아직 연결되지 않은 부분.
- 실제 검사 명령·작업 경로·관련 toolchain/feature/입력·종료 코드·테스트 수·원시 근거 위치.
- 항목별 `PASS` / `FAIL` / `NOT_RUN` / `NOT_APPLICABLE`와 사유, 남은 문제·재개 조건.

`COMPLETE`는 해당 변환과 자체검사의 완료만 뜻한다. 성능 향상·실제 호스트 통합·배포 성공을 검사하지 않고 주장하지 않는다. 기계 검사 통과와 이름·구조·설명의 의미상 적절성 판단을 구분한다.
