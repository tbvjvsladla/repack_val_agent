# 문서발행규칙

## 역할별 배치와 연결

새 개발·변경 과업에는 다음 네 문서를 둔다.

| 폴더 | 역할 | 주요 내용 |
|---|---|---|
| `docs/interview/` | 의도·합의 | 목표·범위·제약·미결정·사용자 결정 |
| `docs/plan/` | 수행 계획 | 순서·영향·완료 기준·검증·복구/재개 |
| `docs/devlog/` | 수행 기록 | 실제 변경·결정·시도·현재 상태·다음 행동 |
| `docs/checklist/` | 검증과 종료 | 기대 조건·관측·상태·근거·독립 검증·수용 |

네 문서를 역할별 폴더에 배치하고 공통 `task_id`로 연결한다. `docs/<task_id>/` 구조로 바꾸지 않는다. 과업 ID는 최초 부여 후 유지하는 고유 문자열이다. 예: `wiki-desk-bootstrap-261103164515`.

각 문서의 frontmatter에는 `task_id`, `document_type`, `title`, `status`, `created`, `updated`를 둔다. `document_type`은 해당 폴더의 역할명이다. 시각은 시간대가 포함된 ISO 8601로 기록한다.

다른 세 문서의 경로는 `related_interview`, `related_plan`, `related_devlog`, `related_checklist` 중 해당 키에 **저장소 상대 전체 경로**로 적는다. 자기 문서는 생략한다. 본문의 클릭 링크는 문서 위치에서 올바르게 해석되는 상대 링크로 쓰고 정본 참조는 frontmatter의 전체 경로로 유지한다.

문서 상태는 실제 단계에 맞게 기록한다. 파일 존재·상태 문자열·권위 순위 자체를 사용자 승인으로 취급하지 않는다. 승인과 검증은 대상·범위·시점·근거를 본문에 남긴다.

plan에는 이번 과업에 선택한 도구·역할, 각 입력과 산출물, 연계 순서·권한·실패 후 반환 조건을 적는다. 스킬에 다른 스킬의 존재·역할·호출 지침을 복제하지 않는다. 환경·의존성·지원 조합·보존 계약·허용 수정 경로도 이번 대상에 맞게 정한다.

checklist에는 자체검사·독립 검토와 실제 통합·기동·시나리오 검사·성능 평가·수용의 항목을 구분한다. 적용 항목마다 기대 조건·실행 대상과 환경·관측·원시 근거·상태를 연결하고, 미적용은 이유를 기록한다. 성능 비교가 필요하면 기준선·대표 입력·환경·품질 조건과 판정 기준을 실행 전에 정한다. 구체 명령·도구 조합·수치는 과업 문서에 두고 일반 헌장을 특정 언어나 Harness에 맞춰 늘리지 않는다.

## 명명과 최초 발행

- 기본: `<YYMMDDHH>_<한글제목>.md`.
- **같은 역할 폴더의 같은 시간대에 이미 발행된 문서가 있으면** 새 문서는 `<YYMMDDHH_MM_SS>_<한글제목>.md`를 사용한다.
- 시각은 **Asia/Seoul** 기준의 실제 발행 시각이다. 역할 접두사를 파일명에 추가하지 않는다.
- 제목은 한국어를 포함한 간결한 `_` slug로 쓰며 필요하면 영문·숫자를 함께 사용한다.
- 새 파일 생성 시 대상이 없음을 확인한다. 초 단위 시각까지 충돌하면 실제 시각을 다시 취득해 같은 규약으로 재시도하거나 충돌을 보고한다. 기존 파일을 덮거나 임의 순번 형식을 추가하지 않는다.

`interview`가 의도를 담고 Planner가 구현 전에 plan·checklist 초안을 작성한다. devlog는 처음에 계획 상태로 만들 수 있으며 수행 사실이 생기면 기록한다. 미래의 실행을 이미 완료한 사실처럼 적지 않는다.

## 동일 과업의 갱신

같은 과업의 후속 수정은 기존 문서와 `task_id`·파일 경로를 유지한다. 파일명의 최초 발행 시각을 최신 수정 시각으로 바꾸지 않는다. `updated`와 본문 변경 이력에 수정 시점·변경 내용·사유를 남긴다.

계획 변경과 실행 결과, 과거 승인·검증 관찰과 현재 판정을 구분한다. 새 결과로 과거 실패·미실행·수용 기록을 지우지 않는다. 관련 조건이 바뀌면 이전 결과의 현재 적용 여부를 `STALE`로 표시하고 필요한 부분만 재검증한다.

원시 근거는 원래 로그·검사 산출물을 참조하고 문서에는 결과와 위치를 남긴다. 문서·구현·과거 실행·이번 실행의 근거 수준을 구분한다. 검증 결과나 로그의 존재만으로 의미상 정답·승인·형식 증명을 주장하지 않는다.

## wiki-desk 입고

스킬 지침은 `.agents/skills/wiki-desk/SKILL.md`, 프로젝트 계약은 `__llm-wiki/contract.json`이다. CLI의 작업 디렉터리는 이 프로젝트 루트다. 다른 디렉터리에서는 CLI 절대 경로와 `--root <프로젝트 루트>`를 함께 쓴다.

wiki-desk의 원문 범위는 `docs/` 하나다. `seed/`, 헌장·스킬 자체, 임시 검증 코드는 입고하지 않는다. 문서 종류는 역할별 경로로 분류하고 문서의 실제 승인 범위는 원문으로 판단한다.

문서를 발행하거나 갱신한 같은 작업 안에서 그 작업의 문서 전체를 입고한다.

```bash
node .agents/skills/wiki-desk/src/cli.ts sync
node .agents/skills/wiki-desk/src/cli.ts sync --apply
node .agents/skills/wiki-desk/src/cli.ts check
```

계획을 먼저 확인한다. 원문 이동·삭제, 사람이 수정한 카드, `verified` 카드의 재확인은 스킬의 보호 절차를 따른다. `protected`·`reverify`·고아·stale을 숨기거나 임의 삭제로 해소하지 않는다. wiki-desk는 원문을 수정하지 않는다. hook·cron·전역 설정을 추가하지 않는다.

## Git 분류

헌장·스킬·과업 문서·위키 카드와 `contract.json`·`glossary.json`·`receipt.json`은 추적한다. 루트 `/seed/`, `/temp/`, `/tests/`, 검색 캐시와 우로보로스 실행 데이터는 제외한다. 루트 `/tests/` 제외를 설치 스킬 내부 회귀 테스트에 적용하지 않는다.
