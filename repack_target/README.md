# repack_target — 개선 대상과 최종 산출물

`repack_target/`는 val_agent가 개선할 콘텐츠를 두는 로컬 작업 공간이다. 스킬, MCP 서버, 플러그인, 라이브러리, 애플리케이션 등 코드베이스와 관련 자산을 대상으로 삼을 수 있다. 개선된 콘텐츠 자체가 과업의 최종 산출물이며, 이 저장소는 개선을 지휘하는 헌장·도구·작성 지침을 배포한다.

이 폴더에서는 **이 README.md만 Git 추적·배포 대상**이다. 나머지 대상 원본·작업본·개선 결과·대상 전용 설정·실행 자료는 모든 깊이에서 val_agent의 Git 추적과 공개본에서 제외한다. 새 clone에는 이 지침만 있으며 실제 대상은 사용자가 별도로 준비한다.

## 두 가지 대상 위치

| 방식 | 대상의 위치 | 지휘와 실행 | Git 관리 |
|---|---|---|---|
| 외부 프로젝트 연결 | val_agent 밖의 기존 작업 공간 | val_agent가 목표·권한·계획·검증을 관리하고, 워커를 실제 대상 루트에 연결한다 | 대상은 원래 위치에서 관리한다. 대상 코드와 개선 결과를 val_agent에 추적하지 않는다 |
| 내부 콘텐츠 개선 | `repack_target/<대상명>/` 등 선택한 실제 콘텐츠 위치 | val_agent가 같은 절차로 개선을 지휘한다. 워커를 연결할 때도 선택한 콘텐츠 루트를 사용한다 | 이 README 외의 모든 콘텐츠와 최종 산출물을 val_agent에서 추적하지 않는다 |

외부 대상을 이 폴더로 옮길 의무는 없다. 내부에 여러 대상이 있으면 과업마다 실제 대상 경로와 수정 범위를 명시한다. 단순히 폴더에 놓인 콘텐츠를 모두 실행·개선할 대상으로 취급하지 않는다.

## 작업할 때 정할 내용

1. 대상 경로·유형·현재 버전 또는 기준선, 원하는 개선과 보존할 동작을 확인한다. Rust 리팩토링, 하네스 개선, 품질·성능 개선 등 구체적인 완료 기준을 정한다.
2. [작업수행규칙](../rules/workflow.md)에 따라 역할·허용 수정 범위·검증·중단과 재개를 계획한다. 과업 문서는 [문서발행규칙](../rules/docs.md)에 따라 val_agent의 `docs/`에 로컬로 작성한다. 오래 걸리는 개선은 [캠페인 규약](../campaigns/README.md)대로 항목과 단계로 나눈다.
3. 워커를 사용할 때는 [worker-agent-control](../skills/worker-agent-control/SKILL.md)의 로컬 `config.json` `workspace` 또는 `--workspace`를 **선택한 대상의 실제 루트**로 정한다. 실제 경로가 든 설정은 로컬에만 둔다. 대상에 존재하는 진입 지침과 필요한 `context_files`를 확인하고, 연결·실행·결과 검증은 선택한 도구의 계약을 따른다. 실제 연결 확인과 본작업 성공은 별도로 판정한다.
4. 구현 결과를 실제 파일·실행 근거·완료 기준으로 확인한다. 대상 자체가 최종 산출물이므로 개선 완료가 val_agent에 대상 소스를 추가하는 이유가 되지 않는다.

## 다른 경로와의 구분

| 경로 | 역할 |
|---|---|
| `skills/` | val_agent의 지휘 작업에 사용하는 스킬의 정본. 재사용 도구로 Git 추적 |
| `.agents/skills/`, `.claude/skills/` | 하네스별 스킬 발견용 디렉터리 심볼릭 링크. 선택 수단 스킬의 링크는 활성화 knob(`skill-activation.yaml`, 로컬 `skill-activation.local.yaml`)에서 켤 때만 생긴다 |
| `seed/` | 참고 원본·조사 자료. 로컬 보관 |
| `temp/` | 임시 검증·공개 후보. 로컬 보관 |
| `repack_target/` | 이번 과업에서 실제 개선할 콘텐츠와 그 결과. 이 지침을 제외하고 로컬 보관 |
| `docs/` | 의도·계획·수행·검증 기록. 역할별 작성 가이드만 배포 |

스킬이 개선 대상이라면 `repack_target/`에 있다는 사실만으로 지휘자의 설치 스킬이 되지 않는다. 개선 대상 스킬을 `skills/`나 발견 링크에 등록하지 않는다. MCP·플러그인도 파일 배치가 설치·등록·활성화를 의미하지 않는다. 참고 자료와 실제 개선 대상의 역할은 과업 문서에서 구분한다.

## 대상 자체의 Git과 별도 배포

이 제외 정책은 **val_agent 저장소의 추적·배포 경계**다. 외부 프로젝트의 자체 Git 정책이나 내부 대상의 독립 저장소 이력을 바꾸지 않는다. 중첩 저장소를 val_agent의 submodule·gitlink로 등록하지 않는다.

대상 자체의 커밋·푸시·패키징·외부 공개는 해당 과업에서 대상 저장소와 허용 범위를 따로 정해 수행한다. val_agent의 커밋·푸시만으로 개선된 대상이 전달되지는 않는다. Git 추적 제외는 백업이나 삭제가 아니며 기존 파일은 로컬에 보존한다.
